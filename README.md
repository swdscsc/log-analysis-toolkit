# log-analysis-toolkit · Web 访问日志分析工具

> 零第三方依赖的 Python 日志分析工具：解析 Nginx/Apache 访问日志，
> 统计 PV/UV、错误率、TOP IP、慢请求、**定位故障接口**，输出控制台摘要 + CSV + 自绘 HTML 报表。

## 为什么做这个

服务器出问题的时候，第一手材料永远是日志。但原始日志几万行起步，肉眼看不出东西。
这个工具解决的正是运维最日常的活：**从日志里快速回答「出了什么事、影响多大、锅在哪个接口」**。

## 快速开始

```bash
# 1. 没有真实日志？先生成一份仿真日志（20000 行，含埋点异常）
python src/gen_sample_log.py --lines 20000 --out sample/access.log

# 2. 跑分析
python src/log_analyzer.py sample/access.log --top 10 --slow 1.0 --out-dir report

# 3. 看结果
#    控制台摘要 / report/report.csv / report/report.html（双击打开）
```

**不需要 pip install 任何东西**，Python 3.8+ 直接跑。

## 实测输出（20,000 行仿真日志）

```
总请求数 : 20,000    独立 IP(UV) : 401
错误率   : 10.85%   5xx 占比 : 5.22%
平均 QPS : 0.17     峰值 QPS : 40 (2026-10-07 01:25:00)
平均耗时 : 203 ms   总流量 : 397.18 MB
慢请求   : 296 条（阈值 1s）

错误最多的接口（故障定位）
  /api/pay/create      错误 673     ← 一眼看出支付接口在崩
  /                    错误 356
```

仿真日志里刻意埋了三类线上特征，工具全部命中：

| 埋的雷 | 工具的发现 |
| --- | --- |
| 高频扫描 IP（占 3% 流量） | TOP IP 榜首 `45.146.164.110` 623 次，是第二名（71 次）的 8.8 倍 |
| 支付接口持续 5xx | 错误接口榜首 `/api/pay/create` 673 次，占其总请求的 59% |
| 1.5% 慢请求 | 慢请求 296 条，最慢 4.99s |

## 功能一览

| 指标 | 用途 |
| --- | --- |
| PV / UV | 流量规模与真实用户数 |
| 状态码分布、错误率、5xx 占比 | 整体健康度 |
| 平均 / 峰值 QPS | 容量评估、判断是否被刷 |
| TOP IP | 识别爬虫、扫描器、CC 攻击 |
| TOP 路径 | 热点接口，缓存与扩容依据 |
| **错误最多的接口** | 故障定位，直接指出该查哪个服务 |
| 接口平均耗时 / 慢请求明细 | 性能瓶颈定位 |
| 每小时请求分布 | 容量规划 |

## 输出物

- `report/report.csv` —— 明细表，可再用 Excel / pandas 二次分析
- `report/report.html` —— 单文件报表（内联 CSS + 手写 SVG 图表），可直接发邮件或归档

## 设计取舍

- **零依赖**：报表图表是手写 SVG 字符串拼出来的，没用 matplotlib。好处是任何机器 clone 下来就能跑，不用配环境。
- **流式解析**：用生成器逐行读，不用 `readlines()` 一次性载入，几百 MB 的日志也不会撑爆内存。
- **脏行不中断**：单行正则匹配失败就跳过计数，不会因为一行畸形日志让整次分析失败。
- **路径去查询串**：`/api/user?id=1` 和 `?id=2` 归并成同一条，否则热点接口会被拆散。
